# 财报智能问答系统（Financial Report RAG QA）

基于检索增强生成（RAG）的财报智能问答系统。输入一份上市公司年报PDF，即可用自然语言提问财务数据、风险信息、业务情况，系统会检索相关原文并生成有据可查的回答。

以伊利股份（600887）2024年年度报告（270页）作为测试数据。

## 技术架构

```
用户提问
   │
   ▼
问题向量化（智谱 embedding-3）
   │
   ▼
FAISS 向量检索（Top-K，带口径感知重排序）
   │
   ▼
拼接 Prompt（检索到的原文 + 问题 + 约束规则）
   │
   ▼
GLM-4-Flash 生成回答
```

**技术栈**：Python · pdfplumber · 智谱 GLM (embedding-3 / GLM-4-Flash) · FAISS

## 评测方法

自建21道问答题，覆盖四类问题：
- **数值查询**（营收、净利润、成本费用等基础财务指标）
- **风险分析**（公司主要风险及应对措施）
- **业务理解**（分业务/分地区经营情况）
- **防幻觉测试**（超出资料范围的问题，检验模型是否会编造答案）

评测方式：批量跑完全部问题后人工核对财报原文，并用独立脚本对回答中的每个数字做字符串级溯源校验（检查是否能在检索到的原文中找到），作为人工判断之外更严格的量化补充。

## 发现的问题与优化过程

这是项目里最有价值的部分——从"跑通demo"到"发现真实问题并针对性修复"的过程。

### 1. 合并口径 vs 母公司口径混淆

**问题**：财报中"总资产""现金流量净额"等指标，合并报表（集团整体）和母公司报表（仅母公司）是两套不同数值。初版系统在未指定口径时，检索经常错误命中母公司口径的表格。

**根因**：分块（chunking）时表格数据和"合并/母公司"标题分离，embedding无法感知这层上下文。

**尝试过但不够可靠的方案**：仅在prompt里写规则"默认使用合并口径"——发现当母公司口径内容的向量相似度略高于合并口径时，模型不会严格遵守这条指令，依然选择相似度更高的候选。

**最终方案**：
1. 扫描财报正文识别"合并资产负债表""母公司利润表"等标题关键词，为该标题后续所有表格打上口径标签，并将标签写入表格内容开头一并做embedding
2. 检索阶段做规则化重排序：多取候选（over-fetch），若问题未明确要求母公司口径，则对标记为"母公司"的候选降权后重新排序

这一步的关键认识：**涉及数据正确性的规则，应该尽量在检索/工程层面强约束，而不是仅依赖prompt指令让LLM"自觉遵守"**。

### 2. LLM算术不可靠

**问题**：即使检索到的原始数字完全正确，模型对这些数字做加减法时仍会出错（同一道减法题三次得到三个不同的错误结果）。

**尝试方案A（Function Calling）**：设计`calculate`工具，要求模型将计算请求交给外部函数执行而非自己心算。实测发现免费版GLM-4-Flash对自定义工具调用支持不稳定——模型有时不会真正触发API层面的`tool_calls`，而是在文本中"伪造"一段看起来像工具调用的内容，未达到预期效果。

**最终方案（更稳健）**：调整策略——发现许多需要"计算"的问题，财报原文其实已经直接给出现成的比例/差值数据（如"变动比例(%)"列），于是改为prompt约束"优先直接引用现成数据，禁止重新计算；确需计算时必须展示完整算式再给结论，便于人工审计"。

### 3. 知识泄漏（Parametric Knowledge Leakage）

**发现**：询问公司高管薪酬明细时，模型给出了一整套看似合理、格式规范的具体数字，但这些数字**不在任何被检索到的原文片段中**（检索到的5个来源页码里没有一个对应薪酬表格）。人名是真实的（模型可能通过训练数据"认识"这家知名公司的高管），但薪酬数字很可能是虚构的。

**意义**：这揭示了RAG系统一个容易被忽视的风险——prompt里写了"仅根据资料回答"，但当模型对某个知名实体存在较强的训练记忆（先验知识）时，无法保证它100%遵守指令、不依赖自身记忆作答。这是学术界称为 *parametric vs. retrieved knowledge conflict* 的真实现象。该问题在本项目中**已识别、未修复**。

## 评测结果

| | 优化前 | 优化后 |
|---|---|---|
| 完全正确 | 13/21 (62%) | 15/21 (71%) |
| 口径混淆错误 | 2题 | 0题（已解决）|
| 算术错误 | 2题 | 1题（部分改善）|
| 疑似知识泄漏 | 1题 | 1题（已识别，未修复）|

数字级溯源校验：核心财务数据可溯源比例约96%（排除评测脚本对编号列表的误判后的修正结果）。

## 已知局限 / 后续改进方向

- 部分含合并单元格的多层表头表格（如分地区/分产品营收明细）解析后字段错位，尚未针对性修复
- 知名实体的"先验知识泄漏"问题尚无有效解法，可能的方向：更强的prompt约束、答案与检索内容的事后一致性校验、或使用对齐更严格的模型
- 目前chunk粒度为整页/整表，未做更细粒度的语义切分实验（如不同chunk size对检索效果的影响）
- 评测集规模较小（21题），可扩展为更大规模、更系统的benchmark
